# トークン定義雛形（命名規則つき）

> [資料キット設計.md](資料キット設計.md) の `design-system/tokens` の確定仕様。
> 作法は **shadcn/ui の theming ＋ Tailwind v4 `@theme`**（実装の主軸）、命名規律は **Adobe Spectrum の3層（global/alias/component）** を採用。
> [共通コンポーネント.md](../FE_architecture/doc/共通コンポーネント.md) ① Tokens 層 = primitive / semantic / component を、そのまま CSS で実体化する。

## 0. 設計原則（なぜこの形か）

- **UI（部品・テンプレ）が直接触ってよいのは semantic だけ**。primitive は参照専用、component はその部品の中だけ。
- **Tailwind v4 の `@theme` に入れた変数だけがユーティリティを生む**性質を利用して、「使ってよいトークン」を機械的に閉じる。
  - semantic / component → `@theme` に入れる（`bg-bg` `p-block` `text-page-h1` などのユーティリティが生える）
  - primitive → `@theme` の外（素の `:root`）に置く＝**ユーティリティが生えない＝直接使えない**
- 色は **shadcn 流の2段名**で持つ: 実体を素名（`--bg` 等）で `:root` に置き、`@theme inline` で `--color-bg: var(--bg)` として公開する。**dark は素名の semantic だけ上書き**すれば、`inline` で生成された utility（`var(--bg)` を直接参照）が runtime で切り替わる。
  - `inline` を使う理由: プレーン `@theme` だと参照値が「定義時のスコープ」で解決され、`--ref-*` を別スコープで差し替えても**黙って効かない**ことがある（[Tailwind: Theme variables](https://tailwindcss.com/docs/theme)）。`inline` 公開＋「dark で触るのは素名 semantic だけ」に限定すれば、この罠が構造的に消える。
  - 寸法・タイポ・半径・コンテナは runtime 差し替えが不要なので、通常の `@theme` で `--ref-*` を参照すれば十分。

## 1. 命名規則

| 層 | 置き場所 | 命名規則 | 例 | UI が使う |
| --- | --- | --- | --- | --- |
| ① primitive（ref） | 素の `:root`（@themeの外） | `--ref-<category>-<scale>` | `--ref-blue-500` `--ref-space-4` `--ref-sand-900` | ✗ 参照専用 |
| ② semantic | 色: 素名 `:root` ＋ `@theme inline` で公開 / 寸法等: `@theme` | `--<tw-namespace>-<role>`（公開名）。色の実体は素名 `--bg` 等 | `--color-fg`(=`var(--fg)`) `--spacing-block` `--text-page-h1` | ◎ これだけ |
| ③ component | `@theme`（utility要る時）/ 素の`:root`（要らない時） | `--<part>-<prop>` | `--spacing-slide` `--slide-w` `--callout-border-w` | △ その部品のみ |

### 規則（lint で機械検知する前提）

1. **生値の直書きは primitive だけ**。semantic は必ず `var(--ref-*)` を参照する。
2. **component は必ず `var(--color-*)` 等の semantic を参照**する（primitive を飛び越さない）。
3. semantic / component の数値直書き・Tailwind 任意値（`p-[24px]` `text-[30px]`）は**禁止**（`eslint-plugin-tailwindcss`）。
4. dark は **素名の semantic 色だけ**（`--bg`/`--fg`/`--accent` 等）上書きする。**`--ref-*`（primitive）と寸法は触らない**（`@theme inline` の解決スコープが崩れ、dark が黙って効かなくなるため）。

### Tailwind v4 namespace 対応（生えるユーティリティ）

| @theme の変数 | 生えるユーティリティ例 |
| --- | --- |
| `--color-fg` `--color-bg` `--color-accent` | `text-fg` `bg-bg` `border-accent` |
| `--spacing-block` `--spacing-slide` | `p-block` `gap-block` `mb-slide` |
| `--text-page-h1` `--text-slide-title` | `text-page-h1` `text-slide-title` |
| `--radius-card` | `rounded-card` |
| `--container-measure` `--container-figure` | `max-w-measure` `max-w-figure` |
| `--font-sans` `--font-mono` | `font-sans` `font-mono` |

## 2. tokens.css 雛形（コピペ可）

`design-system/tokens/tokens.css`。

```css
@import "tailwindcss";

/* =========================================================================
   ① primitive（ref）— 生値・参照専用。@theme の外に置くのでユーティリティは生えない。
   ========================================================================= */
:root {
  /* 色は OKLCH で持つ（広色域・知覚均等・dark の明度調整がしやすい / shadcn 最新準拠）。
     末尾コメントは由来の HEX（人間のレビュー用。実値は OKLCH 側が正）。 */

  /* neutrals（warm / light） */
  --ref-white: oklch(1 0 0);                       /* #ffffff */
  --ref-sand-50: oklch(0.9698 0.0054 95.1);        /* #f6f5f1  surface(light) */
  --ref-sand-600: oklch(0.4815 0.0064 95.19);      /* #5f5e5a  fg-muted(light) */
  --ref-sand-900: oklch(0.2385 0.0037 106.68);     /* #1f1f1d  fg(light) */
  --ref-line-light: oklch(0 0 0 / 0.12);           /* rgba(0,0,0,.12) */

  --ref-ink-900: oklch(0.217 0.0038 106.71);       /* #1a1a18  bg(dark) */
  --ref-ink-800: oklch(0.255 0.0055 106.78);       /* #232320  surface(dark) */
  --ref-ink-300: oklch(0.7242 0.013 96.49);        /* #a8a69d  fg-muted(dark) */
  --ref-ink-100: oklch(0.9245 0.0096 93.57);       /* #e8e6df  fg(dark) */
  --ref-line-dark: oklch(1 0 0 / 0.14);            /* rgba(255,255,255,.14) */

  /* brand */
  --ref-blue-700: oklch(0.3853 0.1096 253.18);     /* #0c447c */
  --ref-blue-500: oklch(0.4814 0.1311 252.49);     /* #185fa5  accent(light) */
  --ref-blue-300: oklch(0.7158 0.114 250.4);       /* #6aa8e8  accent(dark) */

  --ref-radius-1: 4px; --ref-radius-3: 12px;

/* =========================================================================
   ②a semantic 色の実体 — 素名（--bg 等）で :root に持つ。dark はこの層だけ差し替える。
   shadcn 流: トークンを :root/.dark に置き、@theme inline で公開する2段名。
   ========================================================================= */
:root {
  --bg: var(--ref-white);
  --surface: var(--ref-sand-50);
  --fg: var(--ref-sand-900);
  --fg-muted: var(--ref-sand-600);
  --border: var(--ref-line-light);
  --accent: var(--ref-blue-500);
  --accent-contrast: var(--ref-white); /* accent 上に乗る文字 */
  --quote: var(--ref-teal-600);
}

/* dark：素名の色だけ上書き（prefers を既定、data-theme で明示切替）。
   ※ ここで触るのは semantic（素名）だけ。--ref-* は触らない（[Tailwind] 解決スコープの都合）。 */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --bg: var(--ref-ink-900);
    --surface: var(--ref-ink-800);
    --fg: var(--ref-ink-100);
    --fg-muted: var(--ref-ink-300);
    --border: var(--ref-line-dark);
    --accent: var(--ref-blue-300);
    --accent-contrast: var(--ref-ink-900);
    --quote: var(--ref-teal-300);
  }
}
:root[data-theme="dark"] {
  --bg: var(--ref-ink-900);
  --surface: var(--ref-ink-800);
  --fg: var(--ref-ink-100);
  --fg-muted: var(--ref-ink-300);
  --border: var(--ref-line-dark);
  --accent: var(--ref-blue-300);
  --accent-contrast: var(--ref-ink-900);
  --quote: var(--ref-teal-300);

/* =========================================================================
   ②b semantic を @theme に公開してユーティリティを生む。
   - 色: @theme inline ＝ 生成 utility が var(--bg) を直接参照。dark の差し替えが runtime で効く。

   - 寸法/タイポ/半径/コンテナ: 静的（runtime 差し替え不要）なので通常の @theme で ref を参照。
   ========================================================================= */
@theme inline {
  --color-bg: var(--bg);
  --color-surface: var(--surface);
  --color-fg: var(--fg);
  --color-fg-muted: var(--fg-muted);
  --color-border: var(--border);
  --color-accent: var(--accent);

  --text-page-h1: var(--ref-fs-700);
  --text-page-h2: var(--ref-fs-600);
  --text-page-h3: var(--ref-fs-450);

  --text-page-small: var(--ref-fs-300);

  /* text size — deck（スライド） */

  --text-slide-title: var(--ref-fs-900);
  --text-slide-h: var(--ref-fs-600);
  --text-slide-body: var(--ref-fs-500);

  /* spacing（用途名で固定） */
  --spacing-block: var(--ref-space-4);   /* 段落間 */
  --spacing-stack: var(--ref-space-6);   /* ブロック間 */
  --spacing-region: var(--ref-space-10); /* 領域間 */
  --spacing-section: var(--ref-space-14);/* page セクション間 */

  /* radius */
  --radius-card: var(--ref-radius-3);

   ③ component — その部品の中だけ。semantic を参照。utility が要らないものは素の :root。
   ========================================================================= */
:root {
  /* deck キャンバス（SlideFrame が使う・utility 不要） */
  --slide-w: 1280px;
```

## 3. 使用ルール（部品・テンプレ側）

```tsx
// OK：semantic 由来のユーティリティだけ
<div className="bg-surface text-fg p-stack rounded-card border border-border">

// NG：任意値（数値直書き）→ lint で弾く
<div className="bg-[#f6f5f1] p-[24px] rounded-[12px]">

// NG：primitive 直参照（ユーティリティが無いので書けない＝構造的に不可）
```

- 部品の固有寸法が必要になったら **③ component トークンを足してから**使う（部品 CSS に生値を書かない）。
- 新しい意味の色が要るなら **② semantic を足す**（primitive を直接使わない）。

## 4. 図（diagram）トークンの扱い

図の色は ① の `--ref-dia-*` ランプを置き、図 CSS（`Diagram` 部品）がそれを参照する。ライト/ダークの差はこの1か所で吸収する。

```css
/* design-system/components/diagram.css（例） */
svg .c-blue rect { fill: var(--ref-dia-blue-fill); stroke: var(--ref-dia-blue-stroke); }
svg .c-teal rect { fill: var(--ref-dia-teal-fill); stroke: var(--ref-dia-teal-stroke); }
/* dark は @media で --ref-dia-* を上書き or 別クラスで切替 */
```

> 図の中身（ボックス配置・矢印）は **part 固有の `Diagram.tsx` に閉じる**（[資料キット設計.md](資料キット設計.md) 決定4）。色トークンだけ design-system が供給する。

## 5. 採った作法の出典

- **3層を `@theme` で表す / dark を semantic 上書き / 色は OKLCH** … [shadcn/ui Theming](https://ui.shadcn.com/docs/theming)・[Tailwind v4](https://ui.shadcn.com/docs/tailwind-v4)。色のセマンティック化（`bg`/`fg`/`border`/`accent`）も同流儀。shadcn 最新は HSL→OKLCH 変換済みで、本雛形も primitive を OKLCH で持つ（広色域・知覚均等）。
  - **本雛形は shadcn 完全準拠の2段名を採用**: 色は `:root` に素名（`--bg`）で持ち `@theme inline { --color-bg: var(--bg) }` で公開する。`inline` により生成 utility が `var(--bg)` を直接参照するので、dark で素名を差し替えれば runtime 切替が確実に効く。**dark で `--ref-*` を差し替えると Tailwind の解決スコープの都合で黙って効かなくなる**ため、これは lint 規則（規則4）で禁止する（[Tailwind Theme docs](https://tailwindcss.com/docs/theme)）。
- **primitive / semantic / component の3段命名と「参照専用/用途/部品固有」の役割分離** … [Adobe Spectrum design data](https://opensource.adobe.com/spectrum-design-data/)（global/alias/component）。
- **トークンを Style Dictionary 的に「触らず override」** … [nithish-kumar-design/design-tokens](https://github.com/nithish-kumar-design/design-tokens)。
- **アイコン供給元** … 既定 [Lucide](https://lucide.dev)（shadcn/ui エコシステムの既定。ライセンスは ISC＝MIT 同等の許諾）。厳密に MIT が要るなら [Heroicons](https://heroicons.com)（MIT・Tailwind Labs 製）/ [Tabler](https://tabler.io/icons)（MIT）に差し替え可。`Icon` は供給元非依存（`name` を各セットへマップ）。

## 6. 確定／未確定

確定:
- **色は OKLCH**（primitive を OKLCH で保持。HEX は由来コメントとして残す）。
- **例外色 `#854f0b` を `--ref-amber-700` に ref 化**し、`--callout-accent-warn` がそれを参照（生値直書きを撤去）。
- **アイコンは Lucide を既定**（厳密 MIT が要件なら Heroicons / Tabler）。`Icon` 供給元非依存・サイズは `--icon-*`。
- **`@theme inline` 2段名方式（shadcn 完全準拠）を採用**。色は素名 `:root` ＋ `@theme inline` 公開、dark は素名 semantic だけ上書き。

未確定（実装時に詰める）:
- 図ランプの green / amber 追加（同じく OKLCH で）。
- 本体 `@ui` 統合時、素名（`--bg` 等）と本体側トークン名の衝突回避（prefix を付けるか namespace を切るか）。
