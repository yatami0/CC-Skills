# 資料キット設計（doc-kit）— React版・再設計

> [共通コンポーネント.md](../FE_architecture/doc/共通コンポーネント.md) の3層思想を**そのまま** React + Tailwind v4 で実体化する。
> **1つのデザインシステムから、2つの出力モード**を作る:
> - **page（ペライチ）**: 1枚スクロール資料。考えを図で整理する用途（[index.html](index.html) 系）
> - **deck（スライド）**: 固定キャンバスのプレゼン
>
> 旧 [資料作成キット設計.md](資料作成キット設計.md)（Web Components）と PoC（`doc-kit-poc/`）からの**転換**を定義する。

## この再設計の主旨

### (1) 内容を部品に入れない — 関心を3軸に割る

現行PoCの問題＝**「コンポーネントに直接データ（内容）を入れている」**。MDX 内で `<DocSource tag="P1" href="…">TanStack…</DocSource>` のように内容と部品が混ざり、図 `DataflowDiagram` も内容を抱えていた。再設計では:

| 軸 | 持つもの | 持たないもの | 置き場所 |
| --- | --- | --- | --- |
| **デザインシステム**（共通パーツ） | トークン・部品・テンプレ・基盤 | **内容を一切持たない／出力モードに依存しない** | `design-system/`（＝本体 `@ui`） |
| **成果物**（コロケーション） | その資料の内容・原稿・固有の図 | デザイン定義 | `works/<name>/parts/NN/`（＝本体 `features/`） |

> 内容・固有表現は成果物に閉じ、共通側は内容を知らない＝再利用でき、作成は**「原稿.md を書くだけ」**に縮む。

### (2) 出力モードは page / deck の2つ。デザインシステムは共有

部品（②）とトークン（①）は**出力モードに依存しない**。違うのは「並べ方（テンプレ③）」と「動かし方（基盤）」だけ。同じ `Figure` / `CompareTable` / `Callout` / `Sources` が、ペライチのセクション内でもスライド内でも同じように使える。

### (3) 本体決定と一致

本体は既に **ADR-0017「役割3層・トークン固定・任意値禁止」＋ Feature-based/Colocation** を採用済み（[アーキテクチャ設計.md](../FE_architecture/doc/アーキテクチャ設計.md)）。`design-system＝@ui` / `works＝features` はそこにそのまま乗る。

## 全体像

pnpm workspace に2パッケージとして同居（依存は `works → design-system` の一方向のみ）。

```
packages/
  doc-kit-design-system/         ← @doc-kit/design-system（内容なし・モード非依存。将来 @ui へ）
    tokens/      ① Tokens        色・余白・タイポ（page/deck 双方のスケール）
    components/  ② Components     役割9カテゴリ。content-free / container-free
    templates/   ③ Templates     並べ方の定石。モード別に分岐
      page/                       PageDoc / Section（スクロール資料の雛形）
      deck/                       Deck / TitleSlide / FigureSlide / CompareSlide …
    runtime/                     動かし方（モード別）
      page/                       useTOC / useScrollSpy / useTheme / print(flow)
      deck/                       SlideFrame / useDeckNav / PageNumber / print(1枚=1頁)
    index.ts                     公開API（バレル）。成果物はここからだけ import

  doc-kit-works/                 ← @doc-kit/works（成果物。design-system だけに依存）
    nextjs-tanstack/
      doc.config.ts              mode:'page'|'deck'、タイトル、parts の並び
      parts/                     内容の単位（page では section、deck では slide）
        01-intro/原稿.md
        03-dataflow/
          原稿.md                内容（原稿・データ）
          Diagram.tsx            この part 固有の図（共通化しない・インライン）
    scripts/export-pdf.mjs       書き出し（当面 Playwright。本格機構は別途追加開発）
```

作者の基本動作:

1. `works/<name>/doc.config.ts` で `mode`（page or deck）を決める。
2. `works/<name>/parts/NN-xxx/原稿.md` を書く。frontmatter で `layout:` を選ぶ。
3. 終わり。固有の図/構成が要るときだけ同フォルダに `Diagram.tsx` / `Part.tsx` を足す（＝そこに閉じる）。

---

## ① Tokens 層（design-system/tokens）

3段（primitive / semantic / component）。UIが使うのは semantic だけ。**page/deck 両方のスケールを持ち、テンプレが必要な方を参照**する。

```css
@theme {
  /* color（semantic・両モード共通） */
  --color-bg:#fff; --color-surface:#f6f5f1;
  --color-fg:#1f1f1d; --color-fg-muted:#5f5e5a;
  --color-border:rgba(0,0,0,.12);
  --color-accent:#185fa5; --color-quote:#0f6e56;

  /* spacing（用途名で固定＝余白を発明させない・両モード共通） */
  --spacing-block:16px; --spacing-stack:24px; --spacing-region:40px;
  --radius-card:12px;

  /* page（ペライチ）スケール */
  --measure:860px;                 /* 本文最大幅 */
  --text-page-h1:30px; --text-page-h2:23px; --text-page-body:16px;

  /* deck（スライド）スケール */
  --slide-w:1280px; --slide-h:720px;   /* 16:9 固定キャンバス */
  --slide-pad:64px;
  --text-slide-title:48px; --text-slide-h:34px; --text-slide-body:22px;
}
:root[data-theme="dark"] { /* semantic だけ上書き */ }
```

数値直書き禁止は本体 ADR-0017 同様 lint（任意値 `[48px]` 禁止）で機械検知。

## ② Components 層（design-system/components）役割9カテゴリ・content-free / container-free

**全部「見た目だけ」**。文言・URL・図の内容を持たず props/children で受ける。さらに**置かれる器（page/deck）も問わない**。これが2モードでの再利用の核。

| カテゴリ | 部品 | 受け取り方（内容を持たない徹底） |
| --- | --- | --- |
| Layout | `Region`(header/body/footer) `Columns` `Stack` `Grid` `Spacer` `Card` `Divider` | children のみ |
| Display | `Heading` `Text` `Eyebrow` `Figure` `Image` `Icon` | text は children、画像は `src` props |
| DataDisplay | `Bullets` `KeyPoints` `Table` `CompareTable` `Tag` `Stat` | **配列データを props**（`items` `rows` `columns`） |
| Communication | `Callout` `Sources` `Source` `Badge` | tone は props、本文は children/データ |
| Navigation | `Toc` `PageNumber` `ProgressDots` | 基盤が state を props で渡す |
| Action | `Link` | `href` props |
| TextInput / Selection / Overlay | （静的資料では N/A。枠は維持） | — |

比較表は `columns/rows` を**データで**受ける汎用部品にする（中身を JSX 直書きしない）:

```tsx
<CompareTable columns={part.columns} rows={part.rows} />   // 内容を一切知らない
```

## ③ Templates 層（design-system/templates）— 並べ方の定石・モード別

テンプレも content-free。**名前付き slot を持つ枠**で、中身は原稿から流し込む。`pages/XxxPage` 相当。

### page（ペライチ）テンプレ
| Template | slot | 用途 |
| --- | --- | --- |
| `PageDoc` | eyebrow / title / lead / footer / children | 資料1枚の骨格（ヘッダ＋TOC＋本文＋フッタ） |
| `Section` | num / heading / children | 番号付きセクション |

### deck（スライド）テンプレ
| Template | slot | 用途 |
| --- | --- | --- |
| `TitleSlide` | eyebrow / title / lead | 表紙 |
| `SectionDivider` | num / title | 章扉 |
| `BulletsSlide` | title / bullets[] / sources[] | 箇条書き |
| `TwoColumn` | title / left / right / sources[] | 左右2分割 |
| `FigureSlide` | eyebrow / title / figure / caption / sources[] | 図中心 |
| `CompareSlide` | title / columns[] / rows[] / sources[] | 比較表 |
| `SourcesSlide` | title（出典は自動集約） | 引用一覧 |

各テンプレは `components` を組むだけ。例（deck）:

```tsx
export function FigureSlide({ eyebrow, title, figure, caption, sources }: Slots) {
  return (
    <Region>
      <Region.Header><Eyebrow>{eyebrow}</Eyebrow><Heading level={2}>{title}</Heading></Region.Header>
      <Region.Body><Figure caption={caption}>{figure}</Figure></Region.Body>
      <Region.Footer>{sources && <Sources items={sources} />}</Region.Footer>
    </Region>
  );
}
```

`Region` / `Figure` / `Sources` は components（共通）。page の `Section` も同じ部品を組む＝**テンプレが違うだけで部品は共有**。

## 動かし方（design-system/runtime）— モード別

| | page（ペライチ） | deck（スライド） |
| --- | --- | --- |
| 器 | 連続スクロール | 固定キャンバス 1280×720 を scale-to-fit |
| ナビ | `Toc`＋`useScrollSpy`（追従） | `useDeckNav`（←/→/Space・URL `#NN`） |
| 単位 | section | slide |
| PDF | print CSS で自然改ページ（flow） | 1スライド=1ページ（landscape） |
| 共通 | `useTheme`（data-theme）／自動探索（`import.meta.glob`）／出典自動集約 | 同左 |

## 成果物層（works/）— 内容をここに閉じ込める

### 原稿.md の形（frontmatter + Markdown 本文）

frontmatter ＝**構造化データ**（タイトル・箇条書き・比較表・出典）、本文 ＝ prose。**これがその part の全内容**。

```md
---
layout: FigureSlide          # その mode のテンプレ集から選ぶ
eyebrow: 図1
title: 実行時データフロー
figure: ./Diagram            # 固有コンポーネント（同フォルダ）
caption: CRUD の心臓部。コンポーネントは useQuery / useMutation を呼ぶだけ…
sources:
  - { tag: D1, category: データフロー, href: "https://…", text: "Mastering CRUD…" }
  - { tag: D2, category: データフロー, href: "https://…", text: "Complete Guide…" }
---

一覧 → 詳細 → 更新 → 再取得の CRUD ループ。`invalidateQueries` で再取得が走る。
```

### 描画解決（Part.tsx は任意）

基盤が `parts/*/原稿.md` を自動探索しディレクトリ名順に並べ、`doc.config.ts` の `mode` で runtime＋テンプレ集を選ぶ。各 part は:

- **既定**: frontmatter `layout` のテンプレに slot を流し込んで描画。→ **React を書かなくてよい**（＝シンプル）。
- **固有が要るとき**: 同フォルダの `Part.tsx` を基盤が優先。中身は components を組むだけ。
- **固有の図**: `Diagram.tsx` を同フォルダに置き frontmatter から参照。**共通化しない＝そこに閉じる**。marker は `useId()` で自動ユニーク化。

## データの流れ（内容が部品に混ざらない）

```
原稿.md(frontmatter=データ + 本文)  →  基盤が parse  →  Template(slot) に流し込み
                                                       ↘ Components(props/children) で描画
                                                          ↘ Tokens で見た目固定
```

下り一方向。デザインシステムは上流（成果物の内容）を一切参照しない。比較表・箇条書き・出典は frontmatter の**配列データ**として渡るので部品は汎用のまま。出典一覧はページ内データから自動集約。

## ガードレール（分離を機械で守る・ADR-0017準拠）

- **design-system → works の参照禁止**（ESLint `no-restricted-paths` / dependency-cruiser）。共通が内容を import したら即エラー。
- **任意値禁止**（`eslint-plugin-tailwindcss`）。`[48px]` を弾きトークン経由のみ。
- **成果物は design-system の公開APIだけ使う**。生 `<div className="…px">` を制限。
- **components に内容の文字列リテラルを持たせない**（content は props/children のみ）。
- `AGENTS.md` / `CLAUDE.md`: 「資料は 原稿.md ＋ design-system の組み合わせで作る」「新しい見た目は design-system に部品を足す（成果物側に直書きしない）」。

## 本体アーキテクチャとの対応

| 本体（10-FE） | この資料キット |
| --- | --- |
| `packages/@ui`（役割3層・トークン固定） | `design-system/`（tokens/components/templates/runtime） |
| `apps/*/features/*`（Colocation・feature間依存禁止） | `works/*/parts/NN/`（内容を同居・part間依存禁止） |
| 「使用範囲で昇格」→ 共有は packages へ | 複数 part で使う図/部品は design-system へ昇格 |
| 契約生成物は手書き改変禁止 | 出典集約など自動生成物は手で触らない |

## PoC（doc-kit-poc）からの移行ステップ（実装は次フェーズ）

1. `doc-kit-poc/src/kit` を `design-system/`（tokens / components / templates / runtime）に再編。**内容を持つ部品（`DataflowDiagram`）は works 側へ移す**。
2. `CompareTable` / `Bullets` / `Sources` を**データ駆動**（props配列）に作り替える。
3. テンプレを page（`PageDoc`/`Section`）と deck（`TitleSlide`/`FigureSlide`/`CompareSlide`…）に分けて slot 実装。
4. runtime を page（scroll/TOC/print-flow）と deck（SlideFrame/useDeckNav/print-page）で実装。
5. `works/nextjs-tanstack/`（mode: page）に index.html の各節を**原稿.md**として起こす（§3 は `Diagram.tsx` 同梱）。同じ部品で deck 版も1本作り、再利用を実証。
6. lint で分離を固定（任意値禁止・参照方向・content-free）。

## 確定事項

| 論点 | 決定 | 設計への影響 |
| --- | --- | --- |
| 原稿フォーマット | **frontmatter(YAML) ＋ Markdown 本文**（MDX は採らない） | 内容と部品を分離 |
| 出力モード | **page（ペライチ）と deck（スライド）の2モード**。デザインシステムは共有 | 部品/トークン共通、テンプレ・基盤のみモード別 |
| スライド比率 | deck は 16:9（1280×720）既定。page は `--measure` 幅スクロール | — |
| page/deck 相互変換 | **なし**（将来の追加機能とする） | テンプレはモード別に独立。layout 名マッピング表は不要＝設計が単純 |
| `works/` の配置 | **本リポジトリに同居** | リポジトリ内に成果物を置く |
| デザインシステムの育て方 | **モノレポで同居させて育てる**。将来 本体 `@ui` と共有 | pnpm workspace パッケージとして切る（後述） |
| 図(SVG)の扱い | **インライン固有コンポーネントのまま**。書き出し（asset 切り出し等）は別途追加開発 | `Diagram.tsx` を part に同梱。共通化しない |

### モノレポでの位置づけ

本リポジトリの pnpm workspace に2パッケージとして並べ、依存は `works → design-system` の一方向のみ。

```
packages/
  doc-kit-design-system/     ← @doc-kit/design-system（将来 @ui へ統合 or 共有）
  doc-kit-works/             ← @doc-kit/works（成果物。design-system だけに依存）
```

将来 本体 `@ui`（役割3層・トークン固定）と統合しやすいよう、`design-system` の公開APIは @ui の役割カテゴリ命名に寄せておく。
