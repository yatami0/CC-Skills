# 資料作成キット（doc-kit）設計

> [共通コンポーネント.md](共通コンポーネント.md) の3層思想を、`index.html`（技術解説資料）を題材に「再利用できるHTML資料作成キット」へ落とし込んだ設計。
> 既存の1枚 `index.html` を**コンポーネントの組み合わせ**で書けるようにし、同じ部品で別資料も量産できる状態をゴールとする。

## 決定事項（前提）

| 論点 | 採用 | 理由 |
| --- | --- | --- |
| ② Components の実体化 | **Web Components（カスタム要素・Light DOM）** | `<doc-section>` のように要素を組むだけでページになる。「使ってよい部品」の枠が要素名で閉じる。思想（部品の組み合わせでページ化）に最も忠実 |
| 配布形態 | **共有アセット ＋ 資料ごとHTML** | 複数資料を量産する目的に最適。トークン/部品の更新が一括で効く |
| 動的範囲（hook 相当） | **標準セット** | スムーススクロール＋TOCスクロール追従＋モバイルTOC開閉＋テーマ切替。JSは薄く保つ |

- **Light DOM 採用**（Shadow DOM は使わない）: グローバルなトークンCSSをそのまま当てたい／SVG・リンク・印刷・アクセシビリティを素直に扱いたいため。カスタム要素は「意味づけされたタグ＋付随CSS＋任意の振る舞い」として使う。CSSは `doc-section { … }` のようにタグ名へ直接当てる。
- JSが落ちても**本文は表示される**（Light DOMなので中身は素のHTML）。TOCのハイライト等の付加機能だけが無効化される、というデグレード方針。

## 全体像（3層へのマッピング）

```
③ Templates / Patterns … <doc-page>（資料雛形）＋ 出典付きセクション/図/比較表 等の定石
② Components(役割9カテゴリ) … <doc-section> <doc-figure> <doc-callout> … Light DOM カスタム要素
① Tokens(primitive/semantic/component) … tokens.css。色・余白・タイポを3段で固定（数値直書きを止める）
```

## ファイル構成（共有アセット）

```
doc-kit/
  tokens.css        ① primitive / semantic / component トークン（+ ダーク, + data-theme）
  base.css          リセット & 基本タイポ（tokens を参照）
  components.css     ② 全 <doc-*> のスタイル（tokens を参照。タグ名に直接適用）
  diagram.css        図用テーマCSS（c-* / t,ts,th。SVGの色をトークンから導出）
  components.js      ② カスタム要素の登録（<doc-*> を define）
  hooks.js           ③ 振る舞い: useTOC / useScrollSpy / useTheme / useFigureMarkers / useSourceIndex
  doc-kit.css        上記CSSを @import する束ね（資料側はこれ1本）
  doc-kit.js         上記JSを束ねる（type="module"。資料側はこれ1本）

materials/
  nextjs-tanstack.html   各資料 = <doc-*> と本文を組むだけの薄いHTML
assets/                  画像・抽出したSVG等（任意）
```

資料HTMLの冒頭は2行参照するだけ:

```html
<link rel="stylesheet" href="../doc-kit/doc-kit.css">
<script type="module" src="../doc-kit/doc-kit.js"></script>
```

## ① Tokens 層（tokens.css）

3段に割り直す。**UIが直接使ってよいのは semantic だけ**。primitive は参照専用、component は部品テーマ用。

```css
:root {
  /* primitive（生値・参照専用） */
  --space-1: 4px;  --space-2: 8px;  --space-3: 12px; --space-4: 16px;
  --space-6: 24px; --space-8: 32px; --space-12: 48px; --space-14: 56px;
  --fs-300: 13px; --fs-400: 16px; --fs-500: 17px; --fs-600: 23px; --fs-700: 30px;
  --rgb-blue-700:#0C447C; --rgb-blue-500:#185FA5; /* …図の色ランプも primitive に */

  /* semantic（UIが使う層） */
  --color-bg:#fff; --color-bg-subtle:#f6f5f1;
  --color-text:#1f1f1d; --color-text-muted:#5f5e5a;
  --color-border:rgba(0,0,0,.12);
  --color-accent:#185fa5; --color-accent-quote:#0f6e56;
  --space-section: var(--space-14);   /* セクション間 */
  --space-block:   var(--space-4);    /* 段落間 */
  --measure: 860px;                   /* 本文最大幅 */
  --radius-card: 12px;
  --font-sans: system-ui, -apple-system, "Segoe UI", "Hiragino Kaku Gothic ProN", "Noto Sans JP", sans-serif;
  --font-mono: ui-monospace, "SF Mono", Menlo, Consolas, monospace;

  /* component（部品固有テーマ） */
  --card-pad: var(--space-6);
  --toc-width: 280px;
  --callout-border-w: 3px;
}
@media (prefers-color-scheme: dark) { :root { /* semantic を上書き */ } }
:root[data-theme="dark"] { /* テーマ切替ボタン用に同値を上書き */ }
:root[data-theme="light"] { /* 明示ライト */ }
```

- 既存 `index.html` で直書きしている `24px 56px 48px …` を **semantic/component トークンへ寄せる**のがこの層の本丸（「AIが余白を発明する」を止める）。
- 図の `c-*` カラーランプも primitive に置き、`diagram.css` はそれを参照する（ライト/ダークが1か所で決まる）。
- **数値直書きの禁止は lint で機械検知**（後述ガードレール）。

## ② Components 層（役割9カテゴリ・フラット）

資料ドメインで実際に使うのは **Layout / Display / DataDisplay / Navigation / Communication / Action の6つ**。TextInput / Selection / Overlay は静的資料では基本N/A（将来の画像ライトボックスで Overlay が出る程度）。9カテゴリの枠自体は思想どおり維持する。

### コンポーネント・カタログ

| 要素 | 役割カテゴリ | 主な属性 | slot（子） | 由来部分（index.html） |
| --- | --- | --- | --- | --- |
| `<doc-section>` | Layout | `id` `num` `heading` | 本文一式 | `section` + 番号付き `h2` |
| `<doc-card>` | Layout | `variant`(subtle/bordered) | 任意 | `.table-card` `.note-box` 等の土台 |
| `<doc-stack>` | Layout | `gap`(sm/md/lg) | 任意 | 縦リズム |
| `<doc-divider>` | Layout | — | — | `hr` 相当 |
| `<doc-figure>` | Display | `caption` `extra` | `<svg>`/`<img>` | `figure.diagram` ＋ `figcaption` |
| `<doc-image>` | Display | `src` `alt` `caption` | — | 画像 |
| `<doc-table>` | DataDisplay | `variant`(default/compare) | `<table>` | `.table-card`＋`table` |
| `<doc-tag>` | DataDisplay | `tone` | テキスト | `.tag`（[P1] 等） |
| `<doc-toc>` | Navigation | `title` | （自動生成） | `aside.toc` |
| `<doc-callout>` | Communication | `tone`(note/info/warn) `title` | 本文 | `.note-box` |
| `<doc-sources>` | Communication | `title`(既定:出典) | `<doc-source>`× | `.sources` |
| `<doc-source>` | Communication | `tag` `href` | 説明文 | `.sources li` / `.src-list li` |
| `<doc-source-index>` | Communication | `group-by` | （自動集約） | `#sources`（§8 全リンク集） |
| `<doc-key-points>` | Communication | — | `<li>`× | `.key-msgs`（核心メッセージ） |
| （`<a>` 素のまま） | Action | — | — | 引用リンク・アンカー（グローバルCSSで装飾） |

- **入れ子は「使い方」であって分類ではない**: `<doc-stack>` の中に `<doc-tag>` を置いても Tag は Layout の子分類にならない（兄弟のまま）。
- Action(Link) は専用要素を作らず素の `<a>` をグローバル装飾。発明を増やさない方針。

### フラグ（faceted・横断検索/辞書引き用）

役割が主キー、フラグは絞り込み軸。状態を分類から追い出した代わりにここで記録する。

| 要素 | `container` | `anchored` | `cited` | `stateful` | `behaviorHook` |
| --- | --- | --- | --- | --- | --- |
| `<doc-section>` | ✓ | ✓ | — | — | — |
| `<doc-figure>` | ✓ | — | — | — | `useFigureMarkers` |
| `<doc-toc>` | — | — | — | ✓ | `useTOC` / `useScrollSpy` |
| `<doc-source-index>` | — | — | ✓ | ✓ | `useSourceIndex` |
| `<doc-callout>` | ✓ | — | — | — | — |
| `<doc-card>` `<doc-stack>` | ✓ | — | — | — | — |
| `<doc-sources>` `<doc-source>` | ✓ | — | ✓ | — | — |

AIへの辞書引き例:
- 「図に出典を添えたい」→ `<doc-figure>` ＋ 直後に `<doc-sources>`（`cited` を満たす部品を後置）
- 「スクロール追従する目次」→ `role=Navigation かつ behaviorHook=useScrollSpy` → `<doc-toc>`

## ③ Templates / Patterns 層

### Template: `<doc-page>`（資料雛形）

ヘッダ（eyebrow/title/lead）＋ 2カラムレイアウト（`<doc-toc>` サイド ＋ 本文）＋ フッタの骨格を持つ唯一のテンプレート。`pages/XxxPage` 相当＝資料1ファイル。

```html
<doc-page eyebrow="アーキテクチャ解説"
          title="Next.js + TanStack Query のクライアント寄り構成 — 図解"
          lead="…リード文…">
  <doc-toc></doc-toc>
  <doc-section id="intro" num="01" heading="はじめに / プロジェクト背景"> … </doc-section>
  …
  <span slot="footer">フッタ文言</span>
</doc-page>
```

### Pattern（再利用する“作り方”。コードの再利用ではなく定石の踏襲）

| パターン | 組み方 |
| --- | --- |
| 出典付きセクション | `<doc-section>` … 末尾に `<doc-sources>` |
| 図＋キャプション＋出典 | `<doc-figure>` ＋ `<doc-sources>` |
| 比較表 | `<doc-table variant="compare">` |
| 核心メッセージ | `<doc-key-points>`（番号丸つきリスト） |
| カテゴリ別引用一覧 | `<doc-source-index group-by="category">`（ページ内 `<doc-source>` を自動集約・重複排除） |
| 注意書き | `<doc-callout tone="note">` |

## 振る舞い（hooks.js・思想の hook 相当）

状態は役割分類の外へ出し、薄い関数に寄せる。

| hook | 担当要素 | 役割 |
| --- | --- | --- |
| `useTOC` | `<doc-toc>` | ページ内の `<doc-section[id][num][heading]>` を読み目次を自動生成 |
| `useScrollSpy` | `<doc-toc>` | IntersectionObserver で現在セクションをハイライト |
| `useTheme` | `<doc-page>`（テーマ切替ボタン） | `data-theme` を `<html>` に付与・localStorage 永続・初期は `prefers-color-scheme` |
| `useFigureMarkers` | `<doc-figure>` | **SVGの `marker` id を図ごとに自動ユニーク化**（既存 §6 の `arrow1〜4` 手作業を撤廃） |
| `useSourceIndex` | `<doc-source-index>` | ページ内 `<doc-source>` を集約しカテゴリ別一覧を生成 |

`useFigureMarkers` と `useSourceIndex` は、いま手作業/二重管理になっている所を**部品が自動で面倒を見る**ので、量産時の事故が減る。

## ガードレール（AIに発明させない仕掛け）

- **使ってよい要素は `<doc-*>` に限定**。任意の `<div class="…">` で独自スタイルを足すのを規約で禁止。
- **数値直書き禁止**: 資料HTML内の `style="…px"` や生px を lint で検知。余白は属性（`gap="md"`）→トークン経由のみ。
- **生成物の編集禁止**: `<doc-source-index>` 等の自動生成内容は手で触らない。
- `AGENTS.md` / `CLAUDE.md` に「資料は doc-kit の要素だけで組む」「新しい見た目が必要なら部品をキットに足す（資料側に直書きしない）」を明記。

## 次のステップ（実装フェーズの提案順）

1. `tokens.css`（3段トークン）＋ `base.css` を確定（既存の直書き数値を回収）。
2. `components.css` ＋ `components.js` で Layout/Display/Communication の中核（`doc-page` `doc-section` `doc-figure` `doc-card` `doc-callout` `doc-sources/source`）を実装。
3. `hooks.js` の `useTOC`/`useScrollSpy`/`useFigureMarkers` を実装し `doc-toc` `doc-figure` を完成。
4. `doc-table` `doc-tag` `doc-key-points` `doc-source-index` `useTheme` を追加。
5. **既存 index.html を `materials/nextjs-tanstack.html` として新部品で全面書き換え**し、見た目の一致を確認（回帰の基準資料にする）。
6. `AGENTS.md` と lint ルールでガードレールを固定。
