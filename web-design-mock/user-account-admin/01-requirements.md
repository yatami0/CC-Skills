# フェーズ1 — 要件定義

## 何のサイト / 画面か
エンタープライズ向け業務システムの **ユーザー / アカウント管理 一覧画面**。
管理者が社内ユーザー(またはアカウント)を一覧・検索・管理するための内部ツール画面。

## 誰向けか
- システム管理者 / IT 管理者 / 運用担当者(社内利用)。
- データ密度を読み解くことに慣れた業務ユーザー。装飾より一覧性・操作効率を優先。

## トーン
- 機能的・中立・高密度。業務効率重視。装飾は最小限。
- 信頼感と可読性。長時間の利用に耐える落ち着いた配色。

## 採用する哲学 — Apple HIG(ユーザー明示指定により変更)
- **当初は Carbon**(画面タイプ=エンタープライズ管理画面の定石)で mock-v1 を作成。
- **ユーザーの明示指定で Apple に変更**(2026-06-27)。哲学の明示指定は画面タイプ判定より優先(§3)。
- **トレードオフ(記録)**: Apple は高密度データテーブルが本来不得意(Carbon の領域)。
  本プロジェクトでは密度より **余白リズム・Dynamic Type・上質さ** を活かす方向で管理画面を構成する。
- 形状言語の一貫性(Clarity)を重視: アイコンは角丸ライン系、人物はサークルアバターで統一。

## 機能インベントリ(この画面に載せる)
- **左サイドバー(ナビゲーション)** — セクション間移動。
- **検索ヘッダー** — キーワード検索 + フィルタ(ロール / ステータスでの絞り込み)。
- **ユーザー一覧テーブル** — 主要カラムでの一覧表示(下記)。
- **ページネーション** — テーブル下部のページ送り。
- **新規追加** — 「ユーザー追加」アクション(主ボタン)。

## 想定カラム(基本設計で確定)
- 名前 / メール / ロール(管理者・一般) / ステータス(有効・無効・招待中) / 最終ログイン。
- **行アクション列は持たない**(行クリックで詳細表示するため)。

## 制約・留意点
- **ロケール**: 日本語 UI(CJK)。フォントスタック・行高・テーブル可読性に配慮。
- **アクセシビリティ**: Carbon のコントラスト / フォーカス可視 / タッチ・クリック最小サイズを満たす。
- **データ密度**: 1 行 = 1 ユーザー。視線移動を抑えるカラム設計とゼブラ/罫線規律。

## 確定したスコープ(ユーザー検証で確定)
- **一括操作(バルク選択): なし**(チェックボックス列を持たない)。
- **行アクションメニュー: なし**(編集・無効化などの行内メニューは置かない)。
- **行クリックで詳細表示: あり**(行全体クリックで詳細を開く)。
- **ロール: 管理者 / 一般 の 2 種**。

## まだ未確定(後フェーズで詰める)
- 詳細表示の形式(右スライドパネル or 別画面 or モーダル) — 基本設計で決める。
- ステータスの正確な種類と色マッピング(詳細設計でトークン化)。
