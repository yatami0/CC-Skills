# ADR-0003: OpenAPI 駆動の型・API クライアント・バリデーション自動生成

- ステータス: Accepted
- 日付: 2026-06-21
- 関連: ADR-0001, ADR-0002, ADR-0004

## コンテキスト

ADR-0001 でクライアントファースト構成を採用したため、API 境界（BFF ⇄ Spring Boot、および FE ⇄ BFF）での型のズレが実行時エラーの主因になりうる。TanStack Start を採用すれば得られたはずの「エンドツーエンド型安全」を、Next.js 構成でどう代替するかが論点。

幸い、Spring Boot 側が **OpenAPI スキーマを提供できる**。スキーマを単一の真実の源（Single Source of Truth）とし、FE 側の型・API クライアント・入力バリデーションを可能な範囲で自動生成すれば、手書きの型ズレを排除できる。

これは AI 開発との相性が良い。AI が手書きする型は嘘をつくが、スキーマから生成された型は嘘をつかない。生成物がエージェントを縛る「実行可能な仕様」になる（spec-driven development の発想）。

## 決定

**OpenAPI スキーマを真実の源とし、FE 側で型・API クライアント・バリデーションスキーマを自動生成する。手書きの API 型定義は禁止する。**

### 自動生成の範囲と推奨ツール

| 生成対象 | 内容 | ツール例 |
|---|---|---|
| 型定義 | リクエスト/レスポンスの TypeScript 型 | `openapi-typescript` |
| API クライアント | 型付き fetch ラッパ（パス・メソッド・型が一致） | `openapi-fetch`（`openapi-typescript` と同系） |
| バリデーションスキーマ | 入力検証用の Zod スキーマ | OpenAPI → Zod 生成（例: `openapi-zod-client` 等） |

> ツールは候補であり、確定は実装着手時に最新の保守状況を確認して決める。原則（スキーマを源に生成し手書き型を禁止）は変えない。

### 生成と利用のフロー

1. Spring Boot が OpenAPI スキーマ（YAML/JSON）を出力する。
2. CI またはローカルの生成スクリプト（例: `pnpm gen:api`）で、型・API クライアント・Zod スキーマを生成する。
3. 生成物は `src/generated/` 配下に置き、**生成物は人間も AI も手で編集しない**（編集は禁止。再生成で上書きされる前提）。
4. TanStack Query の `useQuery`/`useMutation`（ADR-0002）は、生成された API クライアント関数を呼ぶ。
5. フォーム（ADR-0004 で React Hook Form + Zod を採用）は、生成された Zod スキーマ、または手書き Zod を生成型に整合させて検証する。

### スキーマ更新時の運用

- OpenAPI スキーマが更新されたら再生成する。生成物の差分（型の変更）が型エラーとして表面化し、影響箇所が機械的に分かる。
- CI で「スキーマから再生成した結果がコミット済み生成物と一致するか」を検証し、生成物の更新漏れを検出する（drift 検出）。

## 結果

### 良い影響

- BFF/BE 境界の型ズレが構造的に排除され、TanStack Start の型安全に対する Next.js 側の実質的な回答になる。
- スキーマ変更の影響範囲が型エラーとして自動的に可視化される。
- AI が API の形を推測して手書きする余地が消え、ハルシネーションによる誤った型・誤ったエンドポイント呼び出しを防げる。
- バリデーション（Zod）と型が同じスキーマ由来となり、入力検証と通信の型が一致する。

### 悪い影響・トレードオフ

- 生成パイプラインのセットアップと、スキーマ更新時の再生成という運用が増える。→ スクリプト 1 コマンド化 + CI の drift 検出で運用負荷を抑える。
- OpenAPI スキーマの品質に FE の型安全が依存する。スキーマが実態とズレていれば、FE は「正しく間違える」。→ スキーマは BE 実装から生成する（手書きしない）ことを BE 側と合意する。
- ツールの保守状況に依存する。OpenAPI → Zod 系は型生成系より成熟度にばらつきがある。→ 最悪、Zod は手書きし型のみ生成、という縮退運用も許容する（型生成だけは死守）。

## 補足

- 生成物を `src/generated/` に隔離し、lint/フォーマッタ・レビュー対象から外す（または生成専用の扱いにする）。
- この ADR は ADR-0004（AI 規約）の「API 型・クライアントは手書き禁止、生成物を使う」というルールの根拠となる。
