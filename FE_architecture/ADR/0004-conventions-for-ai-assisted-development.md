# ADR-0004: AI 開発のための規約とガードレール

- ステータス: Accepted
- 日付: 2026-06-21
- 関連: ADR-0001, ADR-0002, ADR-0003, ADR-0005

## コンテキスト

フロントに明るいのは 1 名で、AI コーディングエージェントを主体に開発する。AI は速くコードを書くが、放置すると「もっともらしいが意図とズレたコード（ドリフト）」を生む。1 名運用ではレビュー帯域が限られるため、**判断ポイントを規約で消し、機械的に検証できるガードレール（型・lint・テスト）でエージェントを縛る**必要がある。

Next.js 公式は AI エージェント向けに `AGENTS.md` / `CLAUDE.md` を `create-next-app` で自動生成する仕組みを提供しており、主要エージェント（Claude Code, Cursor, GitHub Copilot 等）はセッション開始時にこれらを読む。これを規約の置き場として活用する。

## 決定

**ADR-0001〜0003 の決定を `AGENTS.md`（および `CLAUDE.md`）に明文化し、加えて lint・型・テストで機械的に強制する。**

### AGENTS.md に明記するルール（骨子）

以下を「やること/やらないこと」として明示する。

**データ取得・更新**
- サーバー状態の取得・更新は TanStack Query（`useQuery`/`useMutation`）に統一する。
- コンポーネント内の `fetch` 直書きを禁止する。
- 独自の `useEffect` + `useState` によるデータ取得実装を禁止する。
- Server Actions を使用しない。サーバー処理が必要なら Route Handler（`app/api/**/route.ts`）に集約する。

**型・API クライアント**
- API のリクエスト/レスポンス型、API クライアント、バリデーション用 Zod スキーマは OpenAPI から生成する（ADR-0003）。
- API 型・API クライアントの手書きを禁止する。`src/generated/` 配下の生成物は手で編集しない。

**コンポーネント方針**
- 画面コンポーネントは原則 Client Component とする（クライアントファースト、ADR-0001）。
- RSC を新規に持ち込む場合は ADR を追加してからにする（勝手に増やさない）。

**フォーム・バリデーション**
- フォームは React Hook Form + Zod に統一する。
- Zod スキーマは更新 API のリクエスト型と整合させる（生成 Zod を使うか、手書き Zod を生成型に合わせる）。

**queryKey 規約**
- ADR-0002 の queryKey 構造に従う。更新成功時はマスタ単位で `invalidateQueries` する。

**ディレクトリ・命名**
- ディレクトリ構成、コンポーネント分割の粒度、ファイル命名はテンプレート（別途 `docs/conventions/` に記載）に従う。

**変更の禁止事項**
- 認証・認可・トークンの扱いに関わる箇所は人間主導とし、AI に自律的に変更させない。
- ライブラリの新規追加・更新は人間がレビューする（AI 単独で依存を増やさない）。

### 機械的なガードレール

規約は文章だけでは守られない。以下で強制する。

- **ESLint ルール**: `fetch` 直書き禁止、`src/generated/` の import 経路の固定、特定 API（Server Actions 等）の使用禁止を lint エラーにする。可能な範囲で `no-restricted-syntax` / `no-restricted-imports` を活用する。
- **TypeScript strict**: `strict: true`。生成型（ADR-0003）と組み合わせ、API 境界の型ズレをコンパイルエラーにする。
- **生成物の drift 検出**: CI で「OpenAPI から再生成した結果 == コミット済み生成物」を検証する（ADR-0003）。
- **テスト**: ADR-0005 の Vitest + Playwright を CI ゲートにする。AI の PR はこのゲートを通過しないとマージ不可とする。
- **CI ゲートはエージェントの実行環境と独立に動かす**。AI はローカルで「動く」と自己納得しがちなため、独立した CI での検証を最終関門にする。

## 結果

### 良い影響

- AI の出力が規約に収束し、1 名運用でもレビュー負荷が下がる。
- 「判断が要る分岐」が減るため、AI のドリフトが起きにくい。
- ルール違反が lint/型/CI で機械的に検出され、人手のレビューに依存しない。

### 悪い影響・トレードオフ

- 初期の規約整備・lint 設定・CI 構築にコストがかかる。ただし 1 名運用ではこの初期投資がレビュー負荷の継続的な削減で回収される。
- 規約が厳しすぎると、正当な例外対応まで阻害しうる。→ 例外は「ADR を追加して合意してから」というメタルールで運用し、規約自体の変更履歴を残す。
- `AGENTS.md` を読まない/古い情報で動くエージェントもありうる。→ 規約は文章だけに頼らず、必ず lint/型/CI の機械的強制と二重化する（文章は説明、強制は機械）。

## 補足

- `CLAUDE.md` は `AGENTS.md` を `@` インポートして内容の重複を避ける（Next.js 公式の推奨構成）。
- 規約の詳細（ディレクトリ構成テンプレート、命名規則、queryKey の具体例）は本 ADR とは別に `docs/conventions/` に置き、ADR は「なぜそうするか」、conventions は「具体的にどう書くか」を担当させる。
