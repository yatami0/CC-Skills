# ADR-0001: フレームワークとレンダリングパラダイムの選定

- ステータス: Accepted
- 日付: 2026-06-21
- 関連: ADR-0002, ADR-0004

## コンテキスト

基幹システムのマスタデータ管理サイト（4〜5画面、CRUD 中心）を構築する。FE/BFF を Next.js が担い、BE は Spring Boot が確定している。フロントに明るいメンバーは 1 名で、AI コーディングエージェントを主体に開発し、規約で挙動を縛る方針。

検討対象は大きく 2 つのパラダイム。

- **サーバーファースト（RSC 中心）**: Next.js App Router の標準。Server Components をデフォルトとし、`'use client'` でクライアント動作にオプトインする。
- **クライアントファースト**: クライアントサイド React を基本とし、必要な箇所だけ明示的にサーバー実行へ寄せる。Next.js 上でも `'use client'` 中心 + クライアント側データフェッチで実現可能。フレームワークごと寄せるなら TanStack Start。

### 判断に効く事実

- **BE が Spring Boot で確定** → Next.js は BFF（REST を叩いて整形する中間層）に徹する。RSC 最大の利点である「Server Component から DB を直接叩く」は、データ実体が常に HTTP 越しの API である本構成では構造的に効かない。
- **CRUD のマスタ管理画面** → SEO 不要・認証の裏側・操作中心。一覧のフィルタ/ソート/ページネーション、更新後の再取得といった「サーバー状態をクライアントで回す」処理が主役。インタラクティブ寄りであり、業界的にもダッシュボード/内部ツールはクライアントファーストが適合とされる領域。
- **フロント 1 名 + AI 開発** → `'use client'` 境界の判断（どこに線を引くか、なぜここで hook が使えないか）は経験者でも頻繁に詰まる。判断ポイントを増やすほど人も AI もブレる。メンタルモデルは 1 つに固定したい。
- **情報量とエコシステム** → 1 名運用では「前例が見つかる」価値が高い。Next.js は情報量・AI の学習データともに豊富で、公式が AI エージェント向けの仕組み（`AGENTS.md` 自動生成）まで提供している。TanStack Start は型安全がエンドツーエンドで魅力的だが、前例が少なく AI が古い/少ない情報で誤りやすいリスクが 1 名運用に重くのしかかる。

## 決定

**Next.js を採用する。ただし RSC を主役に据えず、「Client Components + クライアント側データフェッチ」へ寄せたクライアントファースト構成とする。**

- 画面コンポーネントは原則 Client Component とし、メンタルモデルを「API を叩くクライアントアプリ」に固定する。
- データ取得・更新は ADR-0002 の方針（TanStack Query へ統一）に従う。
- Server Actions は使用しない（ADR-0002 / ADR-0004 で禁止）。BFF が必要なサーバー処理（認証トークンの付与、ヘッダ整形、API アグリゲーション等）は Route Handler（`app/api/**/route.ts`）に集約する。
- TanStack Start は不採用。技術的魅力は認めるが、1 名運用 + AI 開発下では「前例の少なさ = AI の誤りやすさ」のリスクが、得られる型安全のメリットを上回る。エンドツーエンド型安全は ADR-0003 の OpenAPI 駆動の自動生成で代替する。

## 結果

### 良い影響

- 判断軸が「全部クライアント、データは TanStack Query」に一本化され、規約で縛りやすく、AI の出力もブレにくい。
- Next.js の枯れたエコシステムと豊富な情報量を享受できる。
- BFF が必要な箇所は Route Handler に明示的に閉じ込められ、責務が分かれる。

### 悪い影響・トレードオフ

- RSC によるバンドルサイズ削減や初期表示最適化の恩恵は基本的に受けない。ただし対象が認証下の内部管理画面であり、SEO・初回表示の極限最適化は要件ではないため許容できる。
- Next.js を採用しつつ RSC をほぼ使わないため、「なぜ Next.js なのか（CRA や Vite + React でないのか）」という問いが生じうる。回答は、ファイルベースルーティング・Route Handler による BFF・将来的に一部を SSR/RSC へ寄せられる拡張余地・エコシステムと AI 学習データの厚みを 1 つのフレームワークで得られる点にある。
- クライアント側に処理が寄るため、後述の型安全（ADR-0003）とテスト（ADR-0005）でガードしないと、API 境界での実行時エラーを取りこぼしやすい。

## 補足: 却下した代替案

- **RSC 中心の標準構成**: BE が別であるため旨味が薄く、`'use client'` 境界の判断負荷が 1 名運用 + AI 開発と相性が悪い。
- **TanStack Start**: 上記の通り、前例の少なさによる AI 誤り・運用リスクで却下。再評価のトリガーは「エコシステム・AI 学習データが Next.js に比肩する水準まで成熟したとき」。
