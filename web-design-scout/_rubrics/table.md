# 診断ルーブリック — テーブル / リスト

`web-design-scout` の中核。**「なんか違和感がある」を言葉に変える統制語彙**。
各軸は「観察できる属性」だけで構成する(推定の hex 値ではなく、**目で確認できる作法**)。
現行モックと実プロダクトを同じ軸で並べ、ズレを一語で言えるようにする。

> なぜ属性ベースか: 実プロダクトはトークン非公開。正確な px/hex は推定にしかならない(D-shot で
> Primer / Setproduct すら px を出さないことを確認)。**だが「数値は右寄せか」「罫線か枠か」等の
> 作法は観察できる**。曖昧な推定値に頼らず、観察可能な作法で診断する = 地に足が付く。

---

## 0. 使い方(3 ステップ)

1. **現行モックを各軸で値づけ**する(下の表の「値の候補」から1つ選ぶ)。
2. **実例カードを同じ軸で値づけ**する(偵察で集めた各プロダクト)。
3. **一致しない軸を指摘**する ―「あなた=ゼブラ/行高36、Stripe=横罫のみ/行高52」。
   違和感の正体はたいてい 1〜3 軸のズレに収束する。

## 1. 語彙テーブル(軸 × 値の候補)

| # | 軸 | 値の候補(観察で選ぶ) | 何が変わって見えるか |
|---|---|---|---|
| A | **密度モード** | compact / comfortable / spacious | 1画面の行数・詰まり感。power user 系は compact |
| B | **行高の体感** | 詰(〜36px) / 標準(40–48px) / 緩(52px〜) | A の実値。`tabular` データは詰、tap 対象は緩 |
| C | **行の区切り戦略** | 罫線なし / **横罫のみ** / ゼブラ / セル全枠(グリッド) / カード化 | 最も印象を左右。横罫のみが現代SaaSの定石、ゼブラは古典 |
| D | **罫線の濃さ** | 不可視(hover時のみ) / 極淡(地に溶ける) / 明示 | 濃いと「業務システム感」、淡いと「洗練」 |
| E | **数値の整列** | 左寄せ / **右寄せ + tabular-nums** | 右寄せ+等幅数字で桁が揃い比較可能。金額・件数は必須 |
| F | **ヘッダの作法** | 太字 / 全大文字+字間 / 淡色小キャップ / ソート矢印付き | 大文字キャップは「ダッシュボード感」 |
| G | **ステータス表現** | 色ドット+ラベル / 塗りピル / 枠ピル / 淡色tintタグ / テキストのみ | ドット=控えめ(Linear系)、ピル=主張(管理画面系) |
| H | **行アクション** | 常時表示 / **hoverで出現(行末ケバブ)** / 行クリックで詳細 / 一括選択チェック | hover出現が定石。常時表示は雑然 |
| I | **ホバー強調** | なし / 背景薄染め / 左ボーダー強調 / 行浮き | 背景薄染めが標準。行ごとに当たり判定を示す |
| J | **先頭列** | プレーンテキスト / リンク色 / アイコン+主名 / チェックボックス起点 | 主キー列の扱い。リンク色は「遷移できる」signal |
| K | **空状態 / 末尾** | 何もなし / イラスト+CTA / スケルトン | 抜けがちだが「本物感」に効く |
| L | **ページネーション** | なし(無限) / 数字ページャ / load more / 件数+前後 | Primer は 20行/頁を起点に推奨 |

## 2. 診断アウトプットの型(これを返す)

```
■ あなたの現行モック:  A=comfortable / C=ゼブラ / E=左寄せ / G=塗りピル / H=常時表示
■ Stripe(実例):       A=spacious   / C=横罫のみ / E=右寄せ+tabular / G=淡色tint / H=hoverケバブ
─────────────────────────────────────────────────────
差分(違和感の正体): C・E・H の3軸
  → 詰まり/雑然の主因は「ゼブラ(C)」と「アクション常時表示(H)」。
  → 金額が読みにくいのは「左寄せ(E)」。右寄せ+tabular-nums で桁が揃う。
```

> **値は出さず作法で語る**のが鉄則。「#fafafa にしろ」ではなく「ゼブラをやめ横罫のみに」。
> 採用はユーザー。scout は指摘までで、適用は本体モック(web-design-mock)側の責務。
