# 課題: AI生成物の品質が「人」に振られる

- AIで実装の生産量は上がった。しかし**正しさの担保は人間のレビュー頼み**のまま
- 出力品質が次に依存してしまう:
  - **レビュワーの練度** — 見る人によって指摘の質が変わる
  - **プロンプトの質** — 書き手によって生成物の振れ幅が大きい
- 散文で書かれた規約(コーディング規約・設計方針)は、**AIも人も逸脱しうる**

> 結果: 「動くが品質は運次第」。チームを増やしてもスケールしない

# 方針: 正しさを「人」ではなく「機械」に寄せる

- 規約を**散文で書いて終わりにしない**。強制力は機械(型 / lint / CI)に持たせる
- レビュワーやプロンプトの質に依らず、**自動チェックを通らなければマージできない形**で品質を一定に収める

<br>

> 「散文の規約は逸脱しうる。強制力は型 / lint / dependency-cruiser / ArchUnit / codegen:check / contract test に置く。**ここに無い規約は努力目標とみなす**」

# 核: その軸は「契約駆動」

**契約(`contracts/`)を一次情報とし、そこから両世界へ一方向に生成する**

```
contracts/  ──codegen──▶  FE(TS世界)  Next.js/React / api-client / MSW
 (正・人が書く)  │           型・モック・実行時バリデーション
                 └────────▶  BE(Java世界)  Controller / DTO / バリデータ
        ▲
        │ codegen:check(CIで契約⇔コードの差分ゼロを強制)
```

- 方向は常に**契約 → コードの一方向**。コードから契約を生成しない
- 生成物(`generated/`)の**手書き改変を禁止**(再生成で上書きされる前提)
- "実装〜テストの整備" ではなく、**契約を起点に実装・テストまで一貫して機械で守る**

# 人間の力点は「上流の3つ」

機械に寄せるのは下流(生成・実装・検証)。人が責任を持つのは上流:

| 力点 | 中身 | なぜ人か |
|---|---|---|
| **要件定義** | 何を作るか | AIに委ねられない判断 |
| **契約(仕様)定義** | `contracts/` の設計 | **AIに契約を編集させない**(ADR-0009) |
| **アーキ・規約設計** | steering / ADR | 機械ゲートの「基準」そのもの |

> 契約は人が書き、人がレビューする。AIは契約から下流を生成・実装するだけ

# 効果①: スコープ規律で出力が安定する

- 機械強制されたスコープ境界: **1サイクルで触れてよいのは宣言したディレクトリのみ**
- 探索→計画→実装→コミットを分け、plan mode で手順を先に出す

<br>

その結果(副次効果):

- AIが一度に扱う**文脈が小さく絞られる** → 生成物の振れ幅が縮む
- 担当者の練度に依らず一定ライン → **経験の浅いメンバーでもAIを扱いやすい**

> ※ これは設計の「目的」ではなく、スコープ規律から生まれる「効果」

# 効果②: 一次情報の一元化で責任境界がぶれない

- 何が**正(一次情報)か**を契約1か所に固定する
- 生成物は**使い捨て**・手書きしない → 生成物は責任を負う対象ではない
- 人が責任を持つのは**契約とコードだけ**

<br>

> 生成物がいくら増えても、「正は契約・生成物は使い捨て」が固定されているので、
> **責任の所在(どこを直せば正しくなるか)が曖昧にならない**

# 見せ場: 契約駆動の威力が出た2例

**① 双方向 codegen — 契約1つが2つの世界を同時に縛る**
- 契約 yaml を1か所変えると、**FEの型も BEの interface も同時にコンパイルエラー**に
- 契約とコードのズレが**物理的に起きない**

<br>

**② メタ定義駆動 UI(V-5) — 画面実装そのものを消す**
- マスタごとの画面コードを**書かない**
- メタ定義を差し替えるだけで `dept` も `price` も同一ページで動く
- **画面が増えてもコードが増えない**

**PoC = 本番の縮小相似形**。コードは使い捨て、**知見は本番へ持ち越す**
- 持ち越すもの: 契約の書き方 / CI設定 / 破壊テスト手順 / ui-engine 設計知見
- 次フェーズ(BE): V-4(CSV契約) / Java側の双方向codegen / ArchUnit / contract test
- 本番化軸(FE): **React → 本番 Next.js への配線**(設計の核は同形のまま)

<br>

### このPoCで言いたいこと(3点)
1. **課題** — AI生成物の品質がレビュワー・プロンプトの質に振られる
2. **方針** — 正しさを人でなく機械に寄せる
3. **核** — その軸が「契約駆動」(契約=一次情報、一方向codegen)
