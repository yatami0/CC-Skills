# V-5 検証メモ — 実測結果

> 合格基準: 「マスタ個別の画面コードなしで、メタ定義の差し替えだけで 2 種類のマスタ画面が動く」。
> 判定は `services/master/web/test/screen.v5.test.tsx`（jsdom・render→DOM）と `pnpm verify` で機械的に行う。

## 0. 前提: BE プロセスは無い・画面コードは 1 本

- BE は起動しない。データは V-3 と同じく契約 examples から生成した MSW ハンドラ＋override で供給。
- 描画は同一の `<MasterCrudPage masterId>`。マスタ別のコンポーネント/分岐は存在しない（ADR-0003）。

## 1. 画面結合テスト（合格基準そのもの）

```
pnpm test

```

screen.v5.test.tsx の 4 ケース:

| # | ケース | 断言（DOM） |
|---|---|---|
| 1 | dept マスタを描画 | `code` が `<select>`（option 001/002）・`name` が text。unitPrice 入力なし・一覧に unitPrice 列なし |
| 2 | price マスタを**同じページで**描画 | `unitPrice`=number 入力・`effectiveDate`=date 入力。code 入力なし。一覧に契約 example の Pen/Note/120 |
| 3 | 必須未入力で登録 | 「name は必須です」「unitPrice は必須です」をインライン表示・Eraser は出ない（送信されない） |
| 4 | 登録の往復 | 入力して登録 → createRecord の契約 example（Eraser）が MSW 経由で一覧に追加 |

→ #1 と #2 が **同一画面コードで別メタ→別画面** を示す（合格基準）。#3 がバリデーションのメタ駆動、#4 が画面結合（render→DOM）でのモック結合。

## 2. 周辺ゲートが緑のまま（退行なし）

```
pnpm verify   # codegen:check → typecheck → lint → depcruise → test
 codegen:check : 生成物 generated/ に差分なし（V-5 は契約を変えていない）
 typecheck     : 0（strict・tsx 含む）
 lint          : 0（生fetch禁止を tsx へ拡張・react-hooks rules-of-hooks/exhaustive-deps を error）
 depcruise     : no dependency violations found（42 modules, 76 dependencies）
 test          : 8 passed
```

- dependency-cruiser: ui-engine は generated/ を import していない（`generated-only-via-sanctioned-consumers` を満たす）。契約への接点は features（mappers）のみ。
- ESLint: React の Rules of Hooks を機械検知（`eslint-plugin-react-hooks`）。tsx も生fetch禁止の対象。

## 3. 破壊テスト的な確認（メタ駆動経路も契約に縛られている＝V-1 継続）

契約 `MasterMetaField.codeValues` を `codeOptions` にリネーム → 再生成 → 型チェック:

```
pnpm codegen
pnpm typecheck
 services/master/web/src/features/masterRecords/mappers.ts(34,21):
   error TS2339: Property 'codeValues' does not exist on type 'MasterMetaField'.
 packages/api-client/src/generated/poc.msw.ts(20,51):
   error TS2353: 'codeValues' does not exist in type 'MasterMetaField'.
```

→ メタ定義の項目を契約から消すと、写像（features/mappers）がコンパイルエラーで止まる。メタ駆動の画面経路も契約に縛られていることを確認。復帰（`git checkout` + `pnpm codegen`）で緑に戻る。

## 4. 設計判断の記録

| 判断 | 内容 | 理由 |
|---|---|---|
| ui-engine を generated 非依存に | エンジンは独自ドメイン型（MasterUiMeta 等）。generated→エンジン型の写像は features | 汎用描画層を特定契約の生成物に結合させない。dependency-cruiser の sanctioned consumer 制約も満たす |
| 状態は Jotai（読み/書き分離） | store/ に Atom 集約。useMasterCrudState（読）/ useMasterCrudAction（書） | 06-state-and-hooks に準拠。本番設計へ寄せる |
| Next.js を入れない | React + Testing Library で render→DOM を成立 | 合格基準に Next は不要。ランナーは Vitest で本決め。Next 配線は本番化の関心事 |
| 2 つ目メタは MSW override | orval `useExamples` は先頭 example のみ。price は契約と同値を override 供給 | 既存テストの 404 override と同じ流儀。画面コードはメタ出所に非依存で不変 |
| esbuild automatic JSX | `@vitejs/plugin-react` を足さず esbuild で tsx をトランスパイル | 依存を増やさず render→DOM を回す |

## まとめ

- 合格基準（メタ差し替えだけで 2 マスタが render→DOM で動く）を機械判定で満たした。
- 入力 UI・一覧カラム・バリデーションがメタから機械導出される。
- V-3 が経路結合 → 画面結合へ昇格。登録の往復が画面に反映。
- V-1（契約破壊の波及）はメタ駆動経路でも継続して効く。

## 持ち越す知見（本番へ）

- ui-engine のメタ駆動設計（メタ→入力UI / Zod / 一覧 の機械導出、generated 非依存・props 駆動）。
- 契約への静的依存を features（写像）に集約する層分け（V-1 を保ちつつエンジンを汎用に保つ）。
- render→DOM 結合を Vitest(jsdom) + Testing Library + 生成 MSW で軽量に回す構成。
